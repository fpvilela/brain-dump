# Technical Guide — Deploy via Git/GitHub on Hostinger Shared Hosting

## Objective

This guide shows, in a straightforward way, how to configure the deployment of a project hosted in a GitHub repository to Hostinger shared hosting.

The final workflow will be:

```text
Local computer → GitHub → Hostinger
```

In this model:

- the code is versioned on GitHub;
- Hostinger accesses the repository;
- the deploy is made to the directory configured in the hosting panel.

---

## 1. Prerequisites

Before starting, have the following ready:

```text
[ ] Hostinger account with access to hPanel
[ ] Domain or subdomain already configured on Hostinger
[ ] Project versioned in a GitHub repository
[ ] Branch to be published, such as main, master, or dev
[ ] Access to the repository settings on GitHub
```

If the repository is private, you will need to configure an SSH key between Hostinger and GitHub.

---

## 2. Access the Git area on Hostinger

In the Hostinger panel, access the desired website:

```text
Websites → Manage → Advanced → Git
```

Before continuing, confirm that you are on the correct domain or subdomain.

---

## 3. Generate the SSH key on Hostinger

In the Git area of Hostinger, click on:

```text
Generate SSH Key
```

Hostinger will generate a public SSH key.

It usually starts with something like:

```text
ssh-rsa AAAA...
```

or:

```text
ssh-ed25519 AAAA...
```

Copy the entire public key.

---

## 4. Add the SSH key on GitHub

On GitHub, access the project repository.

Then go to:

```text
Settings → Deploy keys → Add deploy key
```

Fill in the fields:

```text
Title: hostinger-project-name-readonly-deploy
Key: paste the public key generated by Hostinger here
```

Leave the option below unchecked:

```text
Allow write access
```

Then click on:

```text
Add key
```

This configuration allows Hostinger to read the repository, but not push changes to it.

---

## 5. Copy the SSH URL of the repository

On GitHub, inside the repository, click on:

```text
Code → SSH
```

Copy the SSH URL of the repository.

Example:

```text
git@github.com:username/project-name.git
```

Use the SSH URL, not the HTTPS URL.

---

## 6. Configure the deploy on Hostinger

Go back to the Git area of Hostinger and fill in the deploy fields.

Example:

```text
Repository Address: git@github.com:username/project-name.git
Branch: main
Directory: domains/mydomain.com/public_html
```

### Repository Address

This is the SSH URL of the GitHub repository.

Example:

```text
git@github.com:username/project-name.git
```

### Branch

This is the branch that will be published on Hostinger.

Examples:

```text
main
master
dev
```

### Directory

On Hostinger, this field may appear as:

```text
Directory
```

It indicates where the project will be published within the hosting environment.

This field does not necessarily need to be filled in. Hostinger itself states that if the field is left blank, the deploy will be made directly to:

```text
public_html
```

That is:

```text
Blank directory → deploy directly to public_html
```

If you want to publish to a specific folder, provide the desired path.

Common example:

```text
domains/mydomain.com/public_html
```

If using a subdomain:

```text
domains/dev.mydomain.com/public_html
```

Before deploying, verify that the destination folder is empty. If the `public_html` folder or the configured directory already has files, the deploy may not be performed correctly by Hostinger.

Therefore, for the first deploy, the ideal steps are:

```text
[ ] Confirm the correct domain
[ ] Confirm the correct directory
[ ] Verify that the destination folder is empty
```

---

## 7. Perform the first deploy

After filling in the information, save the configuration and execute the first deploy manually through Hostinger.

Then, access the domain in the browser and validate:

```text
[ ] The site opened correctly
[ ] The files were published to the correct domain
[ ] CSS and JavaScript loaded correctly
[ ] Images and assets loaded correctly
[ ] The published branch is the expected branch
```

---

## 8. Enable Auto Deployment

After confirming that the manual deploy worked correctly, you can enable Auto Deployment if you want Hostinger to update the project automatically on each `git push`.

With Auto Deployment enabled, the workflow will be:

```text
git push → GitHub → Hostinger → site updated
```

Without Auto Deployment, the workflow will be:

```text
git push → GitHub
```

In this case, you will need to execute the deploy manually in the Hostinger panel.

---

## 9. Basic project update workflow

After the initial setup, the update workflow will be:

```bash
git add .
git commit -m "Description of the change"
git push origin main
```

If Auto Deployment is enabled, Hostinger will deploy automatically.

If it is not enabled, log into the Hostinger panel and execute the deploy manually.

---

## 10. Complete configuration example

Example for a main domain:

```text
Repository Address:
git@github.com:username/institutional-site.git

Branch:
main

Directory:
domains/mydomain.com/public_html

Deploy Key:
hostinger-institutional-site-readonly-deploy
```

Example for a test subdomain:

```text
Repository Address:
git@github.com:username/institutional-site.git

Branch:
dev

Directory:
domains/dev.mydomain.com/public_html

Deploy Key:
hostinger-institutional-site-dev-readonly-deploy
```

---

## 11. Final checklist

Use this checklist before considering the deploy complete.

```text
[ ] Correct repository opened on GitHub
[ ] Correct site opened on Hostinger
[ ] SSH key generated on Hostinger
[ ] SSH key added as Deploy Key on GitHub
[ ] Allow write access unchecked
[ ] SSH URL of the repository copied
[ ] Repository Address filled in
[ ] Correct branch configured
[ ] Correct directory configured or left blank to publish to public_html
[ ] Destination folder empty before the first deploy
[ ] First manual deploy executed
[ ] Site validated in the browser
[ ] Auto Deployment enabled, if necessary
```
